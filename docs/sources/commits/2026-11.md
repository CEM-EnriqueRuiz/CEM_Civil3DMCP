# Commits without an issue: 2026-11

## Declare the civil3d MCP server in `.mcp.json` (2026-11-03)

The user asked for each repo's `.mcp.json` to declare the MCP servers its development needs, and to commit this
without an issue link. Reviews were skipped by the user's decision.

What changed:
- `.mcp.json` gains `"civil3d": { "type": "stdio", "command": "node", "args": ["build/index.js"] }`. The `qmd` entry
  is unchanged.
- `.claude/settings.local.json` adds `civil3d` to `enabledMcpjsonServers`.

Decisions:
- **The entry is project-level, with a relative path and no machine value**, so that it works from any checkout:
  Claude Code starts a project server with the project as its working directory. Rejected: an absolute or
  drive-letter path, and a user-level registration only (`claude mcp add`), because it does not reach other machines.
- **It is enabled in the tracked settings file**, the one that lists the enabled servers. A repo listing only `qmd`
  would not enable the new entry.

`build/` is ignored, so a fresh checkout has to build before the entry can start
([connect an agent](../../workflows/connect-an-agent.md)).

## 2026-11-05, maintenance review (no issue)

Pass 1 of the overnight maintenance review (2026-11-04/05, run `run_00597272b2d2`) left seven applied items
uncommitted. The coordinator re-ran the proof in the morning. On 2026-11-05 the user reviewed the summary and said to
commit and push every repo with no issue link.

What changed and why:
- **A1, leftovers out of the checkout.** 65 old outputs from 2026-10-18 (`setup_log.txt`, `test_plugin_log.txt`,
  `tests/acad_running.txt`, `tests/results/`) were moved out of the repo, and their five `.gitignore` lines (with
  `tests/queue/`) were dropped. Root 0037 says leftovers go, and ignoring them is not enough. Since #82 every script
  writes to `%TEMP%\Cemengal\Civil3DMCP`, so a regression would now show in `git status`
  ([file writes](../../concepts/file-writes.md), [0003](../../decisions/0003-no-acc-writes-temp-folder.md)).
- **A2, `test_plugin.js` deleted.** It was a byte-identical copy of `test_plugin.cjs` and could not run: the package
  is ESM and the script uses `require`.
- **A3, `tests/kill_stale_acad.bat` deleted.** It was a one-night leftover that killed the hard-coded PID 15724 if its
  window said `Dibujo1`. Once Windows reuses that PID, it could kill an unrelated acad.exe that holds unsaved work. It
  had no caller.
- **A4, no false "Connection timed out" warning.** `ConnectionManager.withApplicationConnection` never cleared its
  5 s connect timer, so every successful call logged the warning to stderr 5 s later. One `settle()` now clears the
  timer and the listeners on success or failure. The real timeout path is kept. New test
  `tests/unit/connection.test.mjs` ([MCP server](../../modules/mcp-server.md)).
- **A5, code comments that contradicted the wiki (comments only).** They covered `ScriptSandbox` (a text filter, not a
  sandbox), `PluginEntry` (the bundle, not NETLOAD), `CivilExecution` and `CommandDispatcher` (the captured
  SynchronizationContext and `MCPEXEC`, all six methods), `tests/runner.cjs` (the temp Queue) and
  `C_References/README.md` (setup and Civil 3D 2027). The divergence from upstream is recorded in
  [upstream and fork](../../concepts/upstream-and-fork.md).
- **A6, known gaps found by reading the code.** They are the evidence for P1–P4, P8 and P9, and the CA1416 count is
  now the measured 22 ([known gaps](../../concepts/known-gaps.md),
  [build and deploy](../../workflows/build-and-deploy.md)).
- **A7, `civil3d_skills get` returns the parameters as the skill files declare them.** `extractYamlParameters`
  stripped only the leading `- ` of each parameter block, so the `^key:` regex missed the indented `type:`,
  `required:` and `description:` lines. Every parameter of all 48 skills came back as an optional `string` with no
  description. New test `tests/unit/skills-tool.test.mjs` ([skills library](../../modules/skills-library.md)).

Decisions:
- **Committed without an issue link and without the QA and security reviews**, by the user's choice on 2026-11-05.
  This overrides root 0034 for this commit. A4 had asked for a quick security look at the connection code.
- **A7 stays applied.** It changes what an AI agent sees, so pass 1 flagged it for the user's veto. The user approved
  the summary without vetoing it. Rejected: leaving the wrong types in place, because they told agents that required
  numeric inputs were optional strings.
- **A1 moved the leftovers, it did not delete them.** They sit in the run's scratch folder
  (`removed-leftovers\`), so the change can be reverted. Rejected: keeping the ignore lines, which root 0037 rejects.
- **A5 changes upstream's text in comments only**, with no code change: a diff that ignores comments is empty. This
  keeps upstream merges easy.

Verified:
- `.claude/run-tests.ps1 -Repos civil3dmcp`: node went from 29/29 to 32/32 (three new tests, each red before its fix,
  then green), and xunit stayed at 24/24.
- The plugin Release build has 0 errors and 22 CA1416 warnings, and the wiki lint is 0/0.
- Live checks went through a fresh `civil3d-mcp` server against a fake loopback plugin:
  - `tools/list` returned the 5 tools;
  - a `civil3d_query` round trip worked;
  - stderr showed no false warning in 7 s;
  - all 48 skills matched their files (84 parameters, 0 mismatches).
- Civil 3D was not started and the bundle was not redeployed: no applied item changes how the plugin behaves. The A4
  and A7 fixes reach a running `civil3d` server only after it restarts.

Proposed, not applied (the user's decisions; details in the run report and in [known gaps](../../concepts/known-gaps.md)):
- **P1:** `RpcTcpServer` decodes each 8 KB read on its own, so UTF-8 in a script over 8 KB can be corrupted. Fix:
  one stateful decoder, plus an xunit test over loopback.
- **P2:** a script with top-level `await` would hang Civil 3D's main thread (`task.Wait()`). Options: refuse `await`
  in `ScriptSandbox`, say so in the tool descriptions, or run the script without blocking.
- **P3:** the bundle manifest's `SeriesMin="R25.0"` would let Civil 3D 2025/2026 autoload the net10 DLL. Fix:
  `R26.0`, and `AppVersion` 1.2.0.
- **P4:** in `package.json`, drop the unused `ws`/`@types/ws`, set `main` to `build/index.js`, set version 1.2.0, and
  point the repository and licence to the fork and MIT.
- **P5:** the connect error the AI reads names NETLOAD. Point it to the bundle, `C3DMCPSTATUS` and `C3DMCPSTART`.
- **P6:** `C3DMCPSTATUS` always shows "pending: 0" (upstream's `_queueDepth`). Remove the counter or count real
  pending requests.
- **P7:** unused public upstream members (`PluginRuntime.GetRequired*`/`GetOptionalDouble`,
  `CivilExecution.WriteAsync`, `RoslynExecutor.ClearCache`). Recommendation: keep them, since scripts can reach them
  and deleting them widens the fork.
- **P8:** the Roslyn script cache is keyed by `string.GetHashCode()` with no bound. Fix: key it by the code text or a
  SHA-256, and bound it (LRU).
- **P9:** `SocketClient` keeps each command's 300 s timer after the answer. Fix: clear it, as A4 does for the connect
  timer.
